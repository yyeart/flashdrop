# Модульный монолит до распределения

FlashDrop начинает с одного бинарника и глубоких модулей identity, flashsale и notifications. Выделение API и Core откладывается до прохождения MVP gates, потому что конкурентность, state machine и graceful shutdown можно проверить без сетевого seam, а ранний gRPC добавил бы инфраструктурный шум к учебной задаче. При выделении Core его внешний интерфейс должен сохранить поведение flashsale-модуля.
